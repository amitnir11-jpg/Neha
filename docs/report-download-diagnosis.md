## Confirmed findings

1. The committed `routes/report.js` passes report builders directly to the cache. Cache builders receive `(filters, metadata)`, while report builders interpret their second argument as preloaded report data. A replay using the existing report-cache fixture against committed source produces:
   - Stock Summary: `Cannot read properties of undefined (reading 'filter')`.
   - Category Variance Summary: `Cannot read properties of undefined (reading 'forEach')`.
   - Valuation reconciliation: `Cannot read properties of undefined (reading 'filter')`.

   The complete-audit builder requires Stock Summary; ordinary reports also validate valuation reconciliation. This defect therefore explains local generation failures across those paths. The user's existing uncommitted `cachedReport()` change wraps the builder as `(filters) => builder(filters)`, which fixes the argument mismatch. It was preserved and validated, not rewritten. Whether production is executing this exact report failure requires an authenticated response or logs.

2. `public/ui.js` used `downloadPost()` without any timeout. Complete-audit generation could remain pending indefinitely while fetching headers or reading the workbook body. Its catch handler then discarded server error messages in favor of a generic retry message.

3. Production `GET /api/health` still returns HTTP 503 with `ready=false`, initialization `failed`, database `connected`, 29 startup attempts and the unchanged last-attempt timestamp `2026-10-04T03:50:49.787Z`. The initialization error is `Invalid prisma.$queryRaw() invocation: Server has closed the connection.` The backend recovery defect and existing local fix are documented in `dashboard-loading-diagnosis.md`. This evidence establishes an unhealthy live backend; it does not reveal an authenticated report response or the exact failed SQL.
